# Fabby — Supercharge Microsoft Fabric Copilot Backend

Azure Function (Python v2) that powers the chat widget on the docs site.

## What's new in this version

| Mode | Trigger | Behavior |
|---|---|---|
| **1 — In repo** | Question covered by repo docs/code | Direct, cited answer grounded in **retrieved repo chunks** (docs search index + code manifest) |
| **2 — Fabric, not in repo** | Fabric/Azure topic the repo doesn't cover | Calls Microsoft Learn MCP, cites Learn URLs, **auto-files a `content-gap` GitHub issue** |
| **3 — Off-topic** | Weather, sports, recipes, dating, etc. | Snarky redirect to ask about Fabric, suggests user contact MS sales rep for custom builds |

The Copilot also has a **personality** ("Fabby") — confident, a bit cheeky, never mean. See `function_app.py` `SYSTEM_PROMPT`.

## Files

```
function_app.py          — main HTTP handler + system prompt + /chat /feedback /request routes
repo_grounding.py        — retrieves repo chunks per question (docs search index + code manifest)
build_code_manifest.py   — generates code_manifest.json (notebooks, generators, Bicep modules)
code_manifest.json       — generated; committed so deploys work without a build step
feedback.py              — Azure Table storage for feedback + GitHub issue on thumbs-down-with-comment
ms_learn.py              — Microsoft Learn MCP client (search/fetch tools)
github_issue.py          — files content-gap issues on MS Learn fallback
host.json                — Azure Functions runtime config
requirements.txt         — Python deps (openai, httpx, azure-functions)
local.settings.json.sample — env var template for local dev
```

## Routes

| Route | Purpose | Rate limit |
|---|---|---|
| `POST /api/chat` | Chat with Fabby (grounded in repo + MS Learn fallback) | 20 req/min per IP |
| `POST /api/feedback` | Thumbs up/down per assistant message; down+comment files a GitHub issue | 10 req/5 min per IP |
| `POST /api/request` | `kind=docs-topic` or `kind=problem-report` → files a GitHub issue from repo templates | 5 req/hour per IP |

## Repo grounding

Every `/api/chat` call retrieves relevant repo content before calling the model:

1. **Docs search index** — the MkDocs `search_index.json` published with the docs site (covers `docs/`, `tutorials/`, `poc-agenda/`). Fetched once per instance, cached in memory.
2. **Code manifest** — `code_manifest.json`, generated by `build_code_manifest.py` from notebooks, data generators, and Bicep modules. Loaded from disk at cold start.

Both use a lightweight term-scoring ranker (no embeddings, no extra Azure resources). Retrieved chunks are injected as a system message so Mode 1 answers cite *actual* repo files. If either source is unavailable, the chat still works — grounding is additive, never blocking.

Regenerate the manifest after adding notebooks/generators/Bicep modules:

```bash
python azure-functions/copilot-chat/build_code_manifest.py
```

## Deploy

### Automatic — GitHub Actions (recommended)

A workflow at `.github/workflows/deploy-copilot.yml` deploys this Function on
every push to `main` that touches `azure-functions/copilot-chat/**`.

**One-time setup** (Settings → Secrets and variables → Actions):

| Type | Name | Value |
|---|---|---|
| Variable | `COPILOT_FUNCTIONAPP_NAME` | Your Azure Function App name (e.g. `fabby-copilot-prod`) |
| Variable | `COPILOT_FUNCTION_URL` | *(optional)* `https://<app>.azurewebsites.net/api/chat` — smoke-tested on deploy |
| Secret | `COPILOT_FUNCTIONAPP_PUBLISH_PROFILE` | XML from Azure Portal → Function App → **Get publish profile** |

Without `COPILOT_FUNCTIONAPP_NAME` set, the workflow no-ops and prints the setup hint.

Then in the Azure Portal, under your Function App's **Configuration → Application settings**, set the variables from the tables above.

### Manual — Azure CLI

```bash
az login
az functionapp deployment source config-zip \
  --resource-group <rg> --name <func-app> \
  --src <(cd azure-functions/copilot-chat && zip -r - . -x 'local.settings.json' '__pycache__/*')
```

## Architecture

```
[ Docs site /chat widget ]
            │
            │  POST /api/chat  (CORS-locked to docs origin)
            ▼
[ Azure Function — function_app.chat ]
            │
            ├─ Detects: prompt injection? → block
            ├─ Detects: hard off-topic?   → static snarky reply
            ├─ Otherwise:
            │    │
            │    ├─ repo_grounding.retrieve() ──► MkDocs search_index.json (cached)
            │    │                              └─► code_manifest.json (notebooks/generators/Bicep)
            │    │         └─ chunks injected as system context
            │    │
            │    ├─ Call Azure OpenAI with `search_microsoft_learn` tool
            │    │
            │    ├─ If LLM invokes the tool ──► ms_learn.search_docs() ──► MS Learn MCP
            │    │      └─ On success, github_issue.file_content_gap() ──► GitHub Issues API
            │    │
            │    └─ Return reply + groundedFromRepo / groundedFromMsLearn flags
            ▼
[ Docs site renders the reply ]

[ POST /api/feedback ] ──► feedback.record_feedback()
                              ├─► Azure Table Storage (all events)
                              └─► GitHub Issues (thumbs-down with comment)

[ POST /api/request ]  ──► GitHub Issues (docs-topic / problem-report templates)
```

## Personality cheat-sheet

The system prompt is in `function_app.py:SYSTEM_PROMPT`. Edit the "Personality"
section there to tune Fabby's tone. The snarky off-topic templates live in
`_SNARKY_REDIRECTS` and randomize per request — add more templates to keep
things fresh.
